# Data-converter and sampled-system research

Exactly eight calculations are defined in [data.json](data.json). They cover three basic, three intermediate, and two expert problems. This lane excludes analog noise budgets, analog-filter synthesis, generic passive transients, and digital threshold timing.

The mathematics is established within the stated ideal models. The strongest limitations are not competing formulas but convention differences: reference-span edges versus reconstruction-level endpoints, full-Nyquist SNR versus filtered SNR, dynamic ENOB versus DC noise-free resolution, and full-scale versus half-scale acquisition steps. Physical performance outside these models was not inferred.

## Common implementation contract

- Numerical expressions use only `+ - * / ^`, `floor`, `sqrt`, `abs`, `ln`, and `log10` from the allowed language. Outputs are evaluated sequentially; supporting outputs are included in every worked-example expected map.
- Every constraint uses input keys/constants only, not output keys. Integer resolution/code requirements are expressed using equality to `floor`.
- SI units are used: V, Hz, ohm, F, and s. `bit`, `count`, dimensionless `1`, and dB explicitly identify non-SI counting/logarithmic quantities.
- Finite engineering input bounds keep powers and ratios within floating-point range. Resolution is limited to 32 bits, so code counts remain exactly representable in binary64.
- The default input set for each calculator is the worked-example set. Numerical values were independently calculated from the physical algebra using ordinary arithmetic/logarithms, not generated by the future Rust expression engine. No build, lint, test, formatter, catalog-execution, or hardware verification was run.

## 1. `data.adc_lsb` — Ideal ADC LSB voltage (basic)

**Design question:** What analog input change corresponds to one ideal ADC code-bin width?

Let the full-scale span be `V_span = V_high - V_low`, measured between the outer bin edges, and let integer resolution be N. There are M = 2^N equal bins, so

`q = V_span / 2^N`.

Outputs are `code_count = 2^N` [count] and `lsb_v = q` [V]. Source S1 equation 1 directly gives reference difference divided by 2^N.

**Domain and convention:** N is an integer in [1,32]; V_span is in [1e-9,1e6] V. The denominator is **2^N, not 2^N−1**. If a source instead specifies the separation between its smallest and largest reconstruction levels, that is a different endpoint convention. Ideal resolution alone says nothing about absolute accuracy, missing codes, or analog noise.

**Independent worked example/default:** N = 12, V_span = 3.3 V.

- Count = 2^12 = **4096**.
- q = 3.3/4096 = **0.0008056640625 V**, or **805.6640625 microvolts**.

This is a bin-spacing problem; it does not select the code for a particular input.

## 2. `data.adc_quantization_error` — Ideal ADC code and quantization error (intermediate)

**Design question:** For a specified input, what digital bin is selected and how far is its midpoint reconstruction from the actual voltage?

The model explicitly defines a uniform **midrise** quantizer. Bin k is

`[V_low + kq, V_low + (k+1)q)`, where `q = (V_high−V_low)/2^N`.

Thus

`k = floor((V_in−V_low)/q)`,

`V_hat = V_low + (k+1/2)q`,

`error = V_hat−V_in`, and `absolute_error = abs(error)`.

Since V_in lies in bin k, `−q/2 < error <= q/2`; the maximum absolute error is q/2. S2 distinguishes midpoint-offset/midrise reconstruction from midtread rounding; S3 A.1.1 establishes the ideal ±0.5-LSB error. The floor operation labels the bin; reconstruction is at its **midpoint**, not at its bottom edge. The selected ADC's actual transition convention may differ.

**Domain:** Integer N ∈ [1,32]. V_low, V_high, and V_in lie in [−1000,1000] V; the span must be at least 1 nV. Require `V_low <= V_in < V_high`. A normalized fraction `<1` guard also rejects an input indistinguishable from the upper edge after floating-point normalization. Reject rather than silently saturate out-of-range inputs. Signed analog ranges still produce unsigned straight-binary codes.

**Independent worked example/default:** N = 10, V_low = −1 V, V_high = +1 V, V_in = 0.123 V.

- q = 2/1024 = **0.001953125 V**.
- Normalized input = (0.123+1)×512 = **574.976**, hence code = **574**.
- V_hat = −1 + 574.5/512 = **0.1220703125 V**.
- Signed error = 0.1220703125−0.123 = **−0.0009296875 V**.
- Absolute error = **0.0009296875 V**, below q/2 = 0.0009765625 V.

The discontinuous code/error calculation is physically distinct from merely reporting the bin width.

## 3. `data.bandlimited_quantization_snr` — Bandlimited ideal quantization SNR (expert)

**Design question:** What quantization-limited sine-wave SNR is attainable after restricting digital noise bandwidth, given input amplitude backoff and sample rate?

Let q be the ideal LSB, a ∈ (0,1] the sine's peak-to-peak fraction of full-scale span, f_s the sample rate, and B the one-sided **equivalent noise bandwidth** of the unity-gain digital passband. Under the uniform uncorrelated-error approximation,

`E[error^2] = (1/q) integral from −q/2 to q/2 of error^2 d(error) = q^2/12`.

A white noise spectrum spanning [0,f_s/2] leaves fraction `2B/f_s` of its power in B. Define `OSR = f_s/(2B)`. The retained RMS quantization noise is `q/sqrt(12 OSR)`. The sine RMS is `a V_span/(2 sqrt(2)) = a 2^N q/(2 sqrt(2))`. Dividing yields

`SNR_linear = a 2^N sqrt((3/2) OSR)`,

`SNR_dB = 20 log10(SNR_linear)`.

Equivalently,

`SNR_dB = N*20 log10(2) + 10 log10(3/2) + 20 log10(a) + 10 log10(OSR)`.

The final term is the filtering **process gain**. S4 gives q/sqrt(12) and the ordinary sine SNR; S1 section 2.2 equation 4 establishes the oversampling/filtering 10 log10(OSR) improvement. The mathematical expression uses exact constants rather than rounded `6.02 N + 1.76`.

**Domain:** Integer N ∈ [4,32]; positive f_s and B each in [1e-9,1e12] Hz; B <= f_s/2. a ∈ [1e-6,1] and `a*2^N >=16` to screen out extremely small signals. This 16-LSB-span screen is a disclosed conservative modeling choice, **not** a manufacturer's guarantee of white quantization error. A coherent, undithered tone can produce correlated error even with adequate amplitude. The sine must lie in the filter's unity-gain passband. No noise shaping or real analog noise/distortion is included. Oversampling **without bandwidth-limiting filtering** does not earn this process gain.

**Independent worked example/default:** N=12, f_s=1,000,000 Hz, B=20,000 Hz, a=0.8.

- OSR = 1,000,000/(2×20,000) = **25**.
- RMS ratio = 0.8×4096×sqrt(37.5) = **20066.219972879797**.
- Process gain = 10 log10(25) = **13.979400086720377 dB**.
- SNR = 20 log10(20066.219972879797) = **86.04931137647155 dB**.

At B=f_s/2 and a=1 this reduces to the familiar ideal Nyquist-band sine SNR. For the example, the ideal full-scale unfiltered 12-bit result is about 74.0081 dB; 0.8 amplitude contributes −1.9382 dB and filtering contributes +13.9794 dB.

## 4. `data.dynamic_enob` — Dynamic ENOB from measured SINAD (intermediate)

**Design question:** How many ideal equivalent bits correspond to a real converter's measured full-scale noise-plus-distortion performance?

This calculation consumes a **measurement**, not nominal bit resolution. Equate measured SINAD to the ideal full-scale sine relationship for an equivalent continuous resolution N_eff:

`SINAD_dB = 20 log10(2)*N_eff + 10 log10(3/2)`.

Therefore

`ENOB = (SINAD_dB − 10 log10(3/2))/(20 log10(2))` [bit].

The exact constants are `20 log10(2) = 6.020599913279624` dB/bit and `10 log10(3/2) = 1.760912590556812` dB. S3 A.1.3.5 distinguishes this dynamic measurement from the different noise-based “effective resolution” used in some precision DC ADC specifications. S4 gives the conventional rounded form.

**Domain and limitations:** Measured SINAD ∈ [0,200] dB. It must be obtained from a pure, full-scale sine with a declared full-Nyquist-band measurement that excludes DC but includes harmonics/noise. No backoff correction is applied to sub-full-scale measurements. ENOB need not be integral and is not clipped; sufficiently poor SINAD gives negative equivalent bits. A full-scale measurement is not a prediction of linearity or DC accuracy. This does not separate distortion from random noise.

**Independent worked example/default:** SINAD = 68 dB.

`ENOB = (68 − 1.760912590556812)/6.020599913279624 =` **11.002074272256452 bit**.

**Distinctness from calculation 3:** This is dynamic characterization of a real ADC from **measured combined noise and distortion**, over a specified measurement band. Calculation 3 predicts **in-band quantization-only SNR** from nominal N, amplitude and digital filtering. ENOB is not supplied as another inverse sizing mode of that filtering problem. Its algebra necessarily retains the defining ideal-sine conversion, but the physical question and inputs differ.

## 5. `data.nyquist_sampling_margin` — Baseband Nyquist sampling margin (basic)

**Design question:** Is a selected sample rate above twice the highest preserved baseband frequency, and how much transition space is available before Nyquist?

For uniform real sampling,

`f_N = f_s/2`,

`frequency_margin = f_N−f_max`,

`rate_ratio = f_s/(2 f_max)`.

The spectral replicas of a baseband signal do not overlap when its support is strictly below f_s/2. Source S5 states the theorem and the practical need for input bandlimiting; it explicitly cautions against treating equality as a practical design.

**Domain:** Positive f_s and f_max, each [1e-9,1e12] Hz. A negative margin is a valid result indicating an inadequate design, not grounds to reject the input. Positive margin/rate ratio >1 is the stated ideal no-alias condition; zero margin is a boundary. The reported gap is available transition space, **not** a designed anti-alias filter or guaranteed rejection. Bandpass undersampling is outside this baseband model.

**Independent worked example/default:** f_s = 48,000 Hz, f_max = 20,000 Hz.

- Nyquist = **24,000 Hz**.
- Margin = 24,000−20,000 = **4,000 Hz**.
- Rate ratio = 48,000/40,000 = **1.2**.

## 6. `data.tone_alias_frequency` — Sampled tone alias frequency (intermediate)

**Design question:** At what first-zone frequency will a specified analog tone appear after real-valued sampling?

For sample index n, adding integer k times f_s changes the sinusoid phase by `2 pi k n`, leaving its samples unchanged. Real spectra also identify negative-frequency magnitudes. Select the nearest sample-rate multiple,

`k = floor(f_in/f_s + 1/2)`.

Then the centered remainder lies in [−f_s/2,f_s/2), and

`f_alias = abs(f_in−k f_s)` [Hz]

lies in [0,f_s/2]. S5 sections 3–4 explain periodic spectral replication and folding; this nearest-integer closed form is derived from that replication and uses only allowed expressions. The half-integer tie goes to the higher k, which does not change the magnitude f_s/2.

**Domain:** f_in ∈ [0,1e12] Hz; f_s ∈ [1e-9,1e12] Hz; require f_in/f_s <=1e9 to limit floating-point cancellation when subtracting large multiples. A tone at an exact sample-rate multiple aliases to DC; a tone at `(k+1/2)f_s` aliases to Nyquist. No phase or spectral-inversion direction is promised. ADC track-and-hold input bandwidth remains a separate requirement.

**Independent worked example/default:** f_in = 173,000 Hz, f_s = 48,000 Hz.

- f_in/f_s = 3.6041666…; nearest k = **4**.
- Remainder = 173,000−4×48,000 = −19,000 Hz.
- Alias magnitude = **19,000 Hz**, inside [0,24,000] Hz.

Unlike calculation 5, this diagnoses where an already specified out-of-band component folds; it does not impose or rearrange a no-alias design inequality.

## 7. `data.unipolar_dac_output` — Ideal unipolar DAC output voltage (basic)

**Design question:** What static output voltage does an unsigned DAC code command?

Let integer code D range from 0 through 2^N−1. Let configured gain G include buffer gain/reference division, and reference voltage be V_ref. Then

`configured_span = G V_ref`,

`V_out = D G V_ref / 2^N`,

`maximum_code_v = (2^N−1) G V_ref / 2^N`.

S6 equation 1 directly specifies `DAC_DATA/2^N × VREFIO/DIV × GAIN`; use G=GAIN/DIV. Thus the highest code is **one LSB below** the configured span, not equal to it.

**Domain:** Integer N ∈ [1,32]; integer D ∈ [0,2^N−1]; V_ref ∈ [1e-9,1e6] V; positive G ∈ [1e-6,1000]. Bounds define a generic ideal arithmetic model, not supported settings of the cited part. Supply/output headroom, load current, reference accuracy, static errors and settling must be checked against the actual hardware. The model assumes these are adequate and does not silently rail-limit the result.

**Independent worked example/default:** N=12, D=1234, V_ref=2.5 V, G=2.

- Configured span = 2×2.5 = **5 V**.
- Output = 1234×5/4096 = **1.50634765625 V**.
- Highest-code voltage = 4095×5/4096 = **4.998779296875 V**.

This is digital-to-analog code reconstruction, not a second inverse form of the ADC LSB calculation.

## 8. `data.sar_acquisition_settling` — SAR ADC half-LSB acquisition settling (expert)

**Design question:** How long must a SAR ADC acquire for its sampling capacitor to approach the input closely enough for half-LSB settling?

S7 models sampling-capacitor acquisition through source resistance R_source plus sampling-switch resistance R_switch. Let C_s be effective sampling capacitance and deltaV the initial input-to-capacitor error magnitude:

`tau = (R_source+R_switch) C_s`,

`error(t) = deltaV exp(−t/tau)`.

Half of an N-bit LSB is `V_span/2^(N+1)`. Define `alpha = deltaV/V_span`. Requiring error(t) <= the half-LSB target gives

`exp(−t/tau) <= 1/(alpha 2^(N+1))`,

`t_min = tau ln(alpha 2^(N+1))`.

Outputs are `time_constant_s` [s], `required_time_constants` [1], and `minimum_acquisition_s` [s]. This uses N, the SAR input switching resistance, the sampling capacitor, and the quantization-error target; it is not a generic RC charging waveform or digital logic threshold-delay calculation.

**Initial conditions matter:** For a full-scale error, alpha=1 and t_min=(N+1)ln(2)tau. For half-scale error, alpha=1/2 and t_min=N ln(2)tau. S7's ADS7864 example starts the capacitor at midscale, giving **8.32 tau for 12 bits**; substituting its 8.32 factor into a full-scale initial-error assumption would be incorrect. S7 also recommends extra time-constant margin for that device/application.

**Domain:** Integer N ∈ [1,32]. R_source and R_switch each [0,1e9] ohm, with strictly positive sum. C_s ∈ [1e-15,1e-3] F. Alpha ∈ [1e-12,1], with `alpha 2^(N+1) >1`: the initial error must exceed the target. Inputs already within tolerance are intentionally outside this positive-time calculation rather than being hidden by a fallback. A zero total resistance is excluded because the RC model ceases to represent acquisition.

**Limits:** The source is constant during the acquisition window. Single-pole, constant R/C behavior is assumed. Amplifier slew/recovery, charge buckets, parasitics, multiple poles, charge kickback and switch nonlinearity can dominate actual settling. Values for C_s and R_switch must be sourced from the selected ADC. This does not include conversion time and does not calculate maximum conversion throughput. The theoretical minimum needs hardware/datasheet margin.

**Independent worked example/default:** N=12, R_source=1000 ohm, R_switch=20 ohm, C_s=15 pF=1.5e-11 F, alpha=1.

- tau = 1020×15e-12 = **1.53e-8 s** = 15.3 ns.
- Initial error/target = 2^13 = 8192.
- Required time constants = ln(8192) = **9.010913347279288**.
- t_min = 15.3 ns×9.010913347279288 = **1.3786697421337312e-7 s**, or **137.86697421337312 ns**.

At this time exp(−t/tau)=1/8192, exactly the modeled half-LSB fraction for a full-scale 12-bit step.
