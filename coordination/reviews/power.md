## Finding POWER-R1 — P2: scale RMS before squaring current
- ID/path: power.buck_input_capacitor_rms, backend/catalog/power.json:79.
- Accepted vector: vin=12 V, vout=5 V, iout=1e-200 A, delta_i=0 A. Every scalar bound passes; vin>vout and iout>delta_i/2 hold.
- Static defect: iout^2 rounds to zero in binary64 because 1e-400 is below its smallest subnormal. Zero ripple makes both radicand terms zero. sqrt returns zero; Engine::calculate checks only is_finite(), so this fabricated zero is accepted and returned rather than an arithmetic error.
- Independent expected behavior: waveform variance / TI SSZTBI6 equation 2 yields I_rms=Iout*sqrt(D(1-D))=sqrt(35)/12*1e-200 A, approximately 4.9300664859e-201 A, which is a representable nonzero normal. This is a static IEEE-754 proof, not an observed Rust execution.
- Impact: an admissible positive load is reported as zero capacitor current; direct current squaring also needlessly rejects large currents with representable final RMS.
- Correction: algebraically factor out positive iout: iout*sqrt(duty*((vin-vout)/vin)+duty*(delta_i/iout)^2/12). The existing strict CCM guard bounds delta_i/iout below two, avoiding current-square overflow/underflow. Preserve zero-ripple domain and all nominal oracles. Do not clamp or silently narrow input ranges.
- Parent verification: the complete tiny vector above must return the nonzero oracle with relative tolerance 1e-6 (not a blanket absolute 1e-6). Repeat with iout=1e200 A: expected sqrt(35)/12*1e200 A is finite. Include delta_i=0.6*iout, nominal default, and forbidden iout<=delta_i/2. No checks were executed here.
- Caveat: feature docs acknowledge extreme magnitude issues but describe engine arithmetic errors; they do not justify an accepted zero when the actual RMS is representable.
