## Findings requiring parent action

### SIG-R1 — P2: Preserve the impedance difference before normalizing near a match
- Calculator: `signals.load_reflection`; `backend/catalog/signals.json:580` (added in signal feature patch). Supporting outputs at 586 and 598 inherit the defect.
- Accepted vector: `line_impedance=50`, `load_resistance=50.00000000000001`, `incident_voltage=1`.
- Independent oracle: the load rounds to the next binary64 number above 50, so the exact represented difference is `2^-47`. The real source equation is `(RL-Z0)/(RL+Z0)`; coefficient is approximately `7.105427357601002e-17`, reflected voltage equals it, reflected fraction is approximately `5.048709793414476e-33`.
- Static defect evidence: dividing Z0 by the rounded larger load first rounds to `1-2^-53`; the numerator becomes `2^-53` and the denominator rounds to 2. The implemented coefficient is therefore `2^-54`, approximately `5.551115123125783e-17`, 21.875% low. Squared fraction is approximately `3.0814879110195774e-33` (38.96% low). This is IEEE-754/algebraic prediction, not an executed result.
- Physics evidence: directly inspected Ellingson quarter-wave page gives `Gamma=(ZL-Z0)/(ZL+Z0)` explicitly; TI AN-807 sections 5–6 independently establish boundary voltage/current continuity (PDF equation images are incompletely extracted). Research originally subtracts the impedances before dividing; implementation normalization introduces this additional cancellation.
- Correction: use `((RL-Z0)/M)/(RL/M+Z0/M)` with `M=max(RL,Z0)`. Two nonnegative finite values can be subtracted without overflow; near-match subtraction is exact under Sterbenz's lemma. Keep existing stable near-short load voltage and accepted fraction expressions.
- Verification scenario for Main/Test-signals: test the vector and reversed impedances against high-precision arithmetic on the parsed binary64 inputs; use relative tolerance for tiny nonzero Gamma/reflected voltage/fraction. Also retain exact-match zero, short, nominal, near-open/short and large-impedance-sum regressions.
- Immediate handoff: sent to Main through agent message. Filesystem bus append rejected by available tool; parent persistence requested.

### SIG-R2 — P2: Tie busy-state cleanup to the active calculation request
- Shared frontend; affects all IDs including signals. `frontend/lib/main.dart:87-88`, introduced with the initial substrate.
- Reproducer: start calculation A (revision r), reselect A or switch A→B→A (new revision), then start second A request before the first responds. BackendClient serializes the requests, so second request remains pending when first completes.
- Independent expected behavior: first obsolete request must not mark the second request idle. Calculate button and Enter submission remain disabled until the active request completes.
- Static evidence: result/error handling checks captured revision, but `finally` checks only `calculator.id == _selected?.id`, then clears `_calculating`. Both requests share an ID; first cleanup enables submission while second request is pending. No runtime UI claim.
- Correction: track request ownership separately from selected ID (e.g. monotonic active request token), and permit only current owner to clear busy. Account for ordinary input edits: `_invalidate` increments revision but does not reset `_calculating`, so merely adding revision equality to finally would strand the busy state after an edit.
- Verification scenario for Main: delayed real/controlled subprocess response; start A, reselect A and start second A, resolve only first; second remains busy, old result absent. Resolve second; busy clears and only second result appears. Also edit during a single pending request and ensure completion clears busy without publishing stale output.
- Immediate handoff: sent to Main through agent message. Filesystem bus append unavailable.
