# Sprint backlog — all 128 researched calculators

Status: committed sprint scope; implementation/test/review acceptance is not claimed by this planning record. There are exactly **128 unique calculator rows in 16 lanes**. Every row is Must-have in this sprint; R1/R2 indicate sequencing risk, never a later release. Parent-owned integration work is separately accepted in [SPRINT.md](SPRINT.md), not counted as additional calculators.

## Row contract and handoff

Every row inherits all of these acceptance requirements in addition to its model-specific criterion:

- **A1 Identity and metadata:** preserve the exact ID/title/domain/level and physical boundary from the corresponding object in `research/<lane>.json`; do not split outputs, inverse equations, charge/discharge modes or empirical layer variants into extra features.
- **A2 Formula and units:** promote all output expressions in their declared sequential order; readable formula and topology agree with the research derivation; every input/output has label and explicit unit. Preserve SI and documented exceptions (mil, dB, ppm/K, counts, baud, manufacturing oz/ft²); distinguish RMS/peak/peak-to-peak, absolute K and temperature differences. Model/numerical restrictions are user-visible.
- **A3 Sources and examples:** retain every source title/URL and source-access/evidence caveat from research. `docs/features/<lane>.md` contains an ID section with purpose/topology, derived formula, units, model assumptions, input-domain/error rationale, independently worked substitutions and every expected output. Preserve every researched example input and expected key/value, with declared relative tolerance **1e-6**. Reviewer checks formulas against the cited evidence, including explicit derived extensions, approximations and unavailable-source disclosures; a citation alone is not numerical validation.
- **A4 Error/model validation:** finite inputs exactly match the required keys; bounds include exclusive endpoints; cross-input/input-only constraints execute before outputs. Guard all divisors, logarithms, roots, discrete counts, geometry, operating regions and documented numerical conditioning. Never clamp a bad model, replace nonfinite results with zero, suppress an error, invent a fallback or hide a physically meaningful negative design margin. Preserve permitted signed/zero boundaries specified below. Qualitative conditions not inferable from scalars remain explicit assumptions, not fabricated guarantees.
- **A5 Independent behavioral tests:** `backend/tests/<lane>.rs` evaluates all eight complete examples plus independently derived identities/alternate vectors, at least one admissible boundary and rejection of every meaningful range/cross-input model condition. Use public engine API supplied by parent; do not inspect source text, assert only counts, self-derive goldens from the engine, or reuse runtime results as expected values. For nonzero outputs compare relative error at the declared tolerance; zero/near-zero cases require physically justified output-specific absolute/scale tolerances, not a blanket 1e-6 that hides tiny electrical quantities. Diagnostic design failures intentionally returned as numbers must be tested as successes with negative margins.
- **A6 End-to-end and review:** metadata/forms/results/example controls are usable through parent-owned Flutter UI with no duplicated Flutter numerical logic. Review report associates findings and dispositions with exact IDs. Parent executes the written tests and full desktop acceptance after integration; authoring tests/reports does not claim a pass.

Owners `Dev-<lane>`, `Test-<lane>` and `Review-<lane>` denote the three independent assigned role slots, not additional integration owners. Each lane handoff below supplies its exact research files, writable implementation/test/report paths and branch names. An ID selects the matching JSON object and Markdown model section; all referenced formulas, source links, defaults, constraints and full example inputs remain authoritative. The row's example oracle lists **all expected outputs**, not just a chosen headline value.

R1: expert models and explicit cancellation/discrete/zero-transmission risks, addressed early after one basic catalog/doc commit proves each lane's handoff. R2: remaining models. Both run in the same 16-lane implementation wave and both must close before release. No invented story points, velocity or delivery duration is used.
