# Sprint: all 128 electronics calculators to a verified desktop workbench

## Commitment and scope

One executable sprint implements **every researched calculator: 128 unique IDs, eight in each of exactly 16 implementation lanes**. All are Must-have; there are no feature deferrals, later-release buckets, or substitutions. Research levels are **39 basic, 50 intermediate, 39 expert**. The [complete backlog](BACKLOG.md) supplies 128 explicit owner/acceptance/example rows; the [common board](../RESEARCH_BOARD.md) supplies the full index. These are committed scope, not claims of completed implementation or passing tests.

Goal: users discover any researched model, enter explicit-unit inputs, calculate offline in Rust, and inspect all results, formulas, model limits, sources and worked examples in a real Flutter desktop application. Rust engine, Flutter substrate, native packaging, integration and release acceptance belong to **Main**, not a seventeenth calculator lane. Targets are Linux, macOS and Windows desktop only; no HTTP service, web/mobile UI, simulator, hidden network requirement or duplicated Flutter numerical implementation.

The sprint is gate-based, not a promised calendar interval. There is no historical velocity or validated effort baseline in the supplied material; no story points, fabricated RICE scores or time guarantees are assigned. Equal eight-feature lanes do not imply equal complexity. Protect parent capacity for engine/UI integration, review remediation and desktop evidence. If an external platform prerequisite is unavailable, finish all reachable work and disclose that acceptance gap; do not silently remove features or certify an unexercised platform.

## Executable waves, dependencies and concurrency

**Wave D — 16 developers in parallel.** Main creates all sixteen `feat/<lane>` isolated worktrees from the same G0 baseline; exactly the implementation paths in the table are writable. Manual handoff from an electrical-loss output to a thermal input is optional user workflow, not a required calculator chaining feature.

Each lane finishes exactly eight objects, preserving sequential supporting outputs, defaults, constraints, model assumptions, source evidence and every independent example. Eight one-feature conventional commits are preferred; explain any genuinely inseparable exception rather than fabricating eight empty commits. Publish the ordered explicit commit SHAs, base commit, eight IDs, file list, source/formula changes and unresolved findings on the bus. **G1 — integrate all D handoffs (Main).** Main reviews ownership and provenance, cherry-picks each explicit ordered commit list into integration, resolves only real conflicts with lane authors, and ensures all 128 IDs are present with no silent omissions/rearrangement duplicates. **Wave Q — 16 testers AND 16 reviewers concurrently, independent workstreams.** Testers use `test/<lane>` worktrees rooted at G1 and write meaningful Rust behavioral tests plus addressed JSON-lines/manual desktop scenarios. Maximum **32 concurrent worker agents**: D uses 16; Q uses 16+16=32. Finished researchers/developers must be parked before a full Q launch. If a developer remediation agent remains active, Main queues a Q slot; never exceed the ceiling or pretend 48 workers can run simultaneously. Testing and review are parallel waves on the common snapshot, not serial reviewer approval of tester output. Only Main runs the verification commands after complete handoffs.

**G2 — QA integration and remediation (Main + relevant lane owners).** Main cherry-picks explicit tester commits; reviewer reports already reside at their root paths and Main commits them centrally if appropriate. ## Definition of ready

For every calculator: unique fixed ID and distinct physical question; completed research object/derivation; readable formula plus executable expressions with only supported functions; explicit units/topology/sign conventions; finite complete default/example inputs; all sequential output keys and independently derived expected values; source URLs/evidence caveats; model assumptions and admissible ranges; input-only relational constraints guarding operations and operating region; row-specific test/review criteria in BACKLOG.md. Qualitative assumptions unavailable from numerical inputs remain visible and cannot be silently asserted true.

For every lane: eight reserved IDs with all three levels; own writable files and unique worktree/branch; fixed common base revision; published parent API/JSON-lines schema; shared engine scientific notation, precedence/functions, constraints-before-outputs and error behavior agreed. Parent test API must permit black-box numerical testing without scraping source text.

Specific resolved design issue: `timing.capacitive_crosstalk_peak` originally used cancellation-prone `1-exp(-x)` for valid arbitrarily small positive x. Main approved **Rust f64::exp_m1 / expression `expm1`**, now documented in CONTRACT.md, instead of excluding real fast-edge physics. Dev-timing replaces the expression with stable `divider_limit*(-expm1(-x))/x` or algebraically equivalent safe form, keeps supporting metadata/examples and documents conditioning. Test-timing checks x≈1e-16 convergence to the capacitive-divider limit and zero coupling/swing; Review-timing independently assesses stability and remaining numerical bounds. Design decision is resolved; actual implementation/test/review closure remains part of G1–G3.

## Numerical, protocol and model acceptance

All row-specific criteria and A1–A6 in BACKLOG.md are mandatory. Parent global tests additionally cover:

- Startup catalog validation: 128 unique IDs, eight per lane, allowed levels, complete metadata, finite defaults/expected values, distinct ASCII snake_case keys, no pi/e collisions, resolvable ordered outputs and constraints using inputs/constants only. Counts are structural gates, never the sole behavioral test.
- Grammar: supported arithmetic/functions/constants including scientific notation and `expm1`; unary minus/power precedence; reject malformed, unknown-symbol and unsupported expressions with useful context. Parse definitions once at startup, do not invent per-lane engines.
- Runtime: required inputs exactly match; reject missing/extra fields, wrong types, nonfinite input, out-of-range/exclusive endpoints and model constraints. Catch intermediate/final division/domain errors and nonfinite arithmetic as explicit failures; do not merely check final finiteness after corrupt intermediates. Preserve legitimate negative backfeed, leading Q, skew/slack, overload and infeasible design margins.
- Black-box examples: every expected output of every researched example agrees at its declared 1e-6 relative tolerance; independently justified output-specific absolute tolerances for exact-zero/cancellation boundaries. At least one independent alternate/identity and admissible/rejected boundary per ID; every meaningful range/model guard covered across the lane. Review numerical conditioning beyond just the nominal vector, particularly exponential differences, nearly equal roots, discrete rounding, balance/notch zeros and finite extremes.
- JSON-lines process: offline `catalog`/`calculate`, one JSON response per request line, valid ID/result correlation, no diagnostics on stdout, stderr drained. Unknown command/ID, malformed JSON and invalid requests give explicit errors and do not corrupt a subsequent valid request. No network listener; source links do not need fetching to calculate.
- Engineering interpretation: mathematical tolerance is not physical accuracy; source fits, user-selected design factors and empirical screens never become standards-compliance, SOA, stability, lifetime or hardware-safety certifications.

## Reconciled overlap decisions — retain all 128

No repeated ID or same-physical-problem inverse-only pair was identified in the complete research inventory. All 128 remain. These meaningful near-overlaps require explicit documentation, not deduplication by formula similarity:

- DC current/dissipation and loaded resistive topologies differ from geometric PCB resistance/volumetric heat/energy, semiconductor terminal/channel loss and total converter budgets. Trace generated power is a supporting integral, not another generic resistor-power feature; no lane computes trace temperature as electrical loss.
- General electrical RC/RL/RLC waveforms, digital Schmitt thresholds, SAR half-LSB acquisition and actual thermal heat-storage dynamics answer different model/specification questions. Buffered RC frequency cascades differ from the unbuffered ladder's R1C2 downstream loading. Charge/discharge/inverse timing remain outputs, not new IDs.
- AC series/parallel impedance, exact half-power resonance and lossy-coil zero-susceptance resonance are distinct topologies/objectives. Phase resonance is not impedance maximum; analog filter transfer/component/specification synthesis is not bare resonance. Inductive and capacitive reactance are distinct constitutive laws, not inverse modes.
- LED voltage-fed series limitation versus two-branch total-current-sink matching use different supply/topology questions. Bridge waveform conduction, line reservoir ripple and switch-mode buck/boost capacitor models use different current waveforms. Zener bounds are not LDO regulation loss.
- MOSFET gate-charge supply, damping resistor, Miller timing, overlap and energy-equivalent Coss hard discharge represent separate mechanisms. Diode VR*Qrr is a commutation-cell charge budget, not diode-only heat/MOSFET overlap. Never add these estimates to measured switching energies already containing them.
- Op-amp distinct signal/capacitor topologies, sine large-signal slew, finite-loop small-signal bandwidth and six-source white-noise budget are not gain rearrangements. Noise-gain intermediates are not additional calculators; resistor-ratio common-mode leakage is not intrinsic CMRR.
- ADC code-bin span, deterministic midrise error, bandlimited quantization SNR and measured-full-Nyquist SINAD ENOB differ in conventions/inputs; analog noise-floor dynamic range and noise figure/Friis use different physical sources and power-gain references.
- Ungapped radial toroid and finite-permeability gap reluctance differ in geometry; field-region B²/(2*mu) energy is not separately counted LI²/2. Turns ratio/reflected load, simultaneous winding VA and finite-k coupling have separate objectives.
- Absolute line propagation and PCB two-leg skew differ; single-load first reflection, source-series open-receiver selection and quarter-wave matching are separate boundary problems. Single-pole rise-time equivalent bandwidth is not Nyquist/clock/slew/filter sizing.
- Coupled-victim capacitive crosstalk differs from geometry-based dielectric displacement current; specified parasitic L*di/dt spike differs from closed-path RL trajectory and magnetic energy.
- Feedback junction equilibrium is not constant-power heatsink budgeting's inverse; conduction paths, derating/TCR and unconstrained linear expansion are distinct physical/reliability questions. Empirical/user-fit limits and missing real-material/device data remain caveats, not prerequisite to the offline illustrative model's calculations.
